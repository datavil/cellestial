key/axis helpers in `cellestial/util/utilities.py`, `cellestial/util/errors.py`
and the dataset loaders. Each function was read line by line and exercised on
`pbmc3k` (AnnData, sparse float32 `X`, also opened backed) and `pbmc_cite`
(MuData, two modalities), plus small synthetic objects for edge cases.

Branch: `claude/audit-frames-416226`. Regression tests: `tests/test_audit_frames.py`.

## Confirmed bugs (fixed)

Every fix has a test in `tests/test_audit_frames.py` that failed before the fix
and passes after it.

### 1. `build_frame` with an invalid `axis` raised `UnboundLocalError`

Repro: `cl.build_frame(adata, axis=2)` (also `-1`, `"0"`) ->
`UnboundLocalError: cannot access local variable 'frame'`.
Fix: an `else` branch raises `InvalidArgumentError` naming the accepted values
and the received one. `axis=None` keeps its existing `ValueError`.
Test: `test_build_frame_rejects_invalid_axis`.

### 2. Repeated `variable_keys` crashed with a raw polars error

Repro: `cl.build_frame(adata, variable_keys=["CD14", "MS4A1", "CD14"])` ->
`polars DuplicateError: column with name 'CD14' has more than one occurrence`.
Fix: `anndata_variable_columns` drops repeats (`dict.fromkeys`, order kept),
as it already dropped keys colliding with existing columns.
Test: `test_build_frame_deduplicates_variable_keys`.

### 3. Repeated `metadata_columns` / `dimension_keys` crashed the same way

Repro: `cl.build_frame(adata, axis=0, metadata_columns=["leiden", "leiden"])`
and `dimension_keys=["X_umap", "x_UMAP"]` (case variants of one embedding) ->
`DuplicateError`.
Fix: dedupe `metadata_columns` in both frame builders; `_select_embedding_keys`
skips an embedding already selected.
Tests: `test_build_frame_deduplicates_metadata_columns`,
`test_build_frame_deduplicates_dimension_keys`.

### 4. Missing values in a numeric categorical became a `"nan"` category

Repro: an observation column `pd.Categorical([1, 2, None, 1])` built as
`['1', '2', 'nan', '1']` with zero nulls. Null cells were plotted and legended
as a real group named "nan", and exclude filters could not drop them as null.
Same for variable metadata.
Fix: `part[key].cat.rename_categories(str)` instead of `part[key].astype(str)`.
Strings for present values are identical to before (`str(1) == "1"`,
`str(0.5) == "0.5"`), the dtype stays `pl.Categorical`, missing values stay null.
Test: `test_numeric_categories_keep_missing_values_null`.

### 5. Sparse embeddings crashed frame building

Repro: `adata.obsm["X_sparse"] = csr_matrix(...)`, then
`cl.build_frame(adata, axis=0, include_dimensions=True)` ->
`TypeError: Series constructor called with unsupported type 'csr_matrix'`.
Because `include_dimensions=True` reads every embedding, one sparse entry broke
every frame that asked for dimensions. Same for variable-axis embeddings.
Fix: densify only the requested leading columns (`embedding[:, :column_count].toarray()`)
before slicing. Dense and DataFrame embeddings are untouched.
Test: `test_sparse_embedding_becomes_columns`.

### 6. Single-modality MuData with `modality=None` mistranslated group columns

Repro: `one = MuData({"rna": rna})`; `_modality_source(one, None, "rna:leiden")`
returned the `rna` modality but kept `"rna:leiden"` (the modality calls it
`"leiden"`), and `_container_column(one, None, "leiden")` raised
`KeyNotFoundError ... modality None ... looked for None:leiden`.
`select_modality(None)` already auto-picks the sole modality, but
`modality_column` / `container_column` built their prefix from the literal
`None`. End to end, `cl.dotplot(one, markers=True, group_by="rna:leiden")` failed
with a misleading "`group_by` does not match `rank_genes_groups`" error, while
`modality="rna"` worked; both now behave the same.
Fix: both methods of `_MuDataContainer` resolve `None` to the sole modality
when there is exactly one, mirroring `select_modality`.
Tests: `test_modality_source_translates_column_for_auto_selected_modality`,
`test_container_column_resolves_auto_selected_modality`.

### 7. `from_url` ignored `extension` for URLs without a file suffix

Repro: a `.h5mu` file served at `.../files/download` with `extension=".h5mu"`
was cached as `download` and read with `read_h5ad` ->
`IORegistryError: No read method registered for ... MuData`. The docstring says
`extension` is "the format the downloaded file is read as".
Fix: when the URL-derived filename has no `.h5ad` / `.h5mu` suffix, append
`extension`. URLs that already name a format are unchanged.
Note: such URLs now cache under a new filename (with the suffix), so an earlier
extensionless cache file is downloaded once more.
Test: `test_from_url_reads_extensionless_url_as_requested_format`.

## Edge cases checked, no bug

Guarded by new tests where they protect real behavior:

- Integer `X` keeps integer dtype and values on the AnnData path
  (`test_integer_matrix_keeps_integer_values`).
- Unsorted `variable_keys` map to the right matrix columns
  (`test_variable_values_match_matrix_for_unsorted_keys`); also verified on a
  backed (`backed="r"`) pbmc3k, where sums match the in-memory object.
- MuData variables align to container observations through `obsmap`
  (`test_multimodal_variables_align_with_modality_matrix`).
- `pbmc_cite` loads as a two-modality MuData with 411 cells (`test_pbmc_cite_is_multimodal`).

Checked without a new test: empty `variable_keys` (`[]`, `""`) short-circuit;
`include_dimensions=0` adds no dimensions; negative ints raise; DataFrame
embeddings work through `_as_array`; MuData modality masks are excluded from
`obsm` / `varm`; duplicate variable names raise `AmbiguousVariableError` only
when a requested key is duplicated; string categoricals keep nulls.

## Open issues (not fixed)

- **O1. Default id column collides with a metadata column of the same name.**
  `adata.obs["Barcode"] = ...` makes `cl.build_frame(adata, axis=0)` and
  `cl.umap(adata, key="leiden")` fail with polars `DuplicateError`, because the
  default `observation_id_column="Barcode"` is added next to the metadata column
  (same for `variable_id_column="Variable"`). Not fixed: the right behavior is a
  design decision (skip the metadata copy, rename the id column, or raise a
  clear error that names `observation_id_column`), and most plots do not expose
  the id column name. Needs the user's call.
- **O2. A string passed as `metadata_columns` or `dimension_keys` is split into
  characters.** `metadata_columns="leiden"` raises
  `KeyError: metadata_columns not found in observations: ['l', 'e', 'i', 'd', 'e', 'n']`.
  The types say `Sequence[str]`, so this is caller error, but the message is
  misleading. Either accept a single string (as `variable_keys` does) or reject
  it with a clear message; left for the user to choose. The same missing-key
  path also raises a bare `KeyError` without a close-match suggestion, against
  the error rules in AGENTS.md; changing the class could break `except KeyError`.
- **O3. An AnnData without `X`** (layers only) raises
  `TypeError: 'NoneType' object is not subscriptable` from
  `fetch_variable_columns`. Rare; a clear error (or a layer argument) would be
  better, but there is no layer parameter on this path to point users to.
- **O4. `_reject_sequence_key` lets sets and arrays through.**
  `cl.umap(adata, key={"CD14"})` and `key=np.array([...])` fail later with
  `TypeError: unhashable type`. It only rejects `Sequence` instances, which
  matches its docstring, so this is a gap rather than a bug.
- **O5. `_resolve_tooltips` passes any string through.** Only `"none"` is a
  valid string (`Literal["none"]`), but `tooltips="CD14"` is returned as-is and
  reaches the backend unvalidated.

## Improvement suggestions (lower priority)

- `anndata_observations_frame` and `anndata_variables_frame` duplicate the
  metadata and dimension loops line for line; a shared helper would keep fixes
  like bugs 3 to 5 from having to be applied twice.
- `_resolve_embedding_key` lists `Rest:` from a `set`, so the warning text order
  varies between runs; sorting it would make warnings reproducible.
- `_determine_axis` and the `_are_*` helpers return `True` for an empty key
  list (`all([])`), so `_determine_axis(data, [])` returns 1 instead of failing;
  callers currently never pass an empty list.
- `build_frame(axis=True)` is accepted as axis 1 because `True == 1`.
- `_MuDataContainer.container_column(None, column)` on a multi-modality object
  reports "modality `None`" when the column is missing; callers reach it only
  after `select_modality` has already rejected `None`, so it is cosmetic.

## Bug-hunting pass

A separate reviewer (cheaper model) re-tested the fixes adversarially: numeric
categoricals (int, uint8, float with NaN, float32, bool, empty, ordered,
near-equal floats such as `2**53` and `2**53 + 1`), sparse CSR/CSC embeddings
with `include_dimensions` above the width, case-variant `dimension_keys`,
`modality=None` with one or several modalities, and every caller of
`_modality_source` / `_container_column`. It confirmed no bugs; its two cosmetic
observations are the last two suggestions above.
