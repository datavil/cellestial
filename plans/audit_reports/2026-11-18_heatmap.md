# Audit: heatmap family, annotated heatmap, layout, histogram (2026-11-18)

Audited on top of branch `dev` (after the lower-memory `_bin_within_groups`).
Scope: the rows of `plans/audit_AI.md` with blank check cells under
`cellestial/single/heatmap/`, `cellestial/complex/` and related helpers.
Every function was read line by line and run on `pbmc3k` (17041 cells; the
`cell_type_lvl1` column has 1767 null cells). Numbers were cross-checked
against an independent numpy/pandas computation. Plots were rendered to PNG
and inspected. Regression and edge-case tests are in
`tests/test_heatmap_audit.py`.

## Confirmed bugs (fixed)

### 1. Dendrogram with non-string categories crashes `heatmap` and `annotated_heatmap`

Reproduction:

```python
a.obs["integer_cluster"] = pd.Categorical(a.obs["leiden"].astype(int))
cl.heatmap(a, keys, "integer_cluster", dendrogram=True)
# SchemaError: datatypes of join keys don't match - `_group_key`: str ... i64
cl.annotated_heatmap(a, keys, "integer_cluster", dendrogram=True)
# InvalidOperationError: cannot use values of type `i64` to replace values in a column of type `str`
```

Cause: `_get_dendrogram` returned `categories_ordered` as stored (integers), while
every frame compares groups as strings. `_get_dendrogram_tree` already converted.

Fix: `_get_dendrogram` returns `str(category)` labels (`cellestial/util/dendrogram.py`).

Test: `test_dendrogram_with_integer_categories_renders` (all five plots).

### 2. Stored dendrogram that does not match the data gives internal errors

Reproduction (dendrogram computed, then a group removed by subsetting):

```python
sc.tl.dendrogram(a, groupby=g)
b = a[a.obs[g] != "Monocytes"].copy()
cl.heatmap(b, keys, g, dendrogram=True)            # ValueError: fp and xp are not of the same length.
cl.annotated_heatmap(b, keys, g, dendrogram=True)  # KeyError: 'Monocytes'
```

And the reverse (dendrogram lacks a group the data has): `heatmap`, `matrixplot`,
`dotplot`, `annotated_heatmap` raised polars `InvalidOperationError: incomplete
mapping specified for replace_strict`; `stacked_violin` silently dropped that
group's violins.

Fix: new `_check_dendrogram_groups` in `cellestial/util/dendrogram.py`, called
after the group order is known. A data group missing from the dendrogram always
raises `DendrogramMismatchError`. Dendrogram groups without cells raise only in
the per-cell views (`heatmap(aggregate=False)`, `annotated_heatmap`), which cannot
place a leaf without rows; the aggregated views keep drawing an empty row, as before.
Messages match the existing `tracksplot` wording.

Tests: `test_dendrogram_with_groups_absent_from_data_raises`,
`test_dendrogram_missing_data_groups_raises`.

### 3. Duplicate keys give a raw polars error

Reproduction: `cl.dotplot(a, ["CD3D", "LYZ", "CD3D"], g)` raised
`polars.exceptions.DuplicateError` (same for the other four plots). A key repeated
inside one mapping group raised "appears in multiple groups: 'T' and 'T'".

Fix: `_resolve_key_groups` raises `DuplicateKeysError` ("`keys` contains duplicates:
[...]. Pass each key once.", the `tracksplot` wording) for flat keys, and a
dedicated message for a key repeated within one group. `annotated_heatmap` now
resolves its keys through `_resolve_key_groups`.

Tests: `test_duplicate_keys_raise_duplicate_keys_error`,
`test_duplicate_key_within_one_key_group_names_the_group`.

### 4. `annotated_heatmap` shows or hides null-group cells depending on `max_rows`

Reproduction: with `group_by="cell_type_lvl1"` (1767 null cells), the binned
plot (default `max_rows=1000`) dropped the null cells because
`_bin_observations` joins on the group column, and allocated only 89 of 100 bins.
With fewer cells than `max_rows` (or `max_rows=None`) the null cells were kept and
drawn as an unlabelled block, first in dendrogram order.

Fix: `annotated_heatmap` filters null-group rows right after building the frame,
as `heatmap`, `dotplot` and `stacked_violin` already do.

Test: `test_annotated_heatmap_drops_null_group_rows_with_and_without_binning`.

### 5. `histogram` has no x-axis title

The shared distribution theme blanks `axis_title_x` (right for violins and
boxplots, whose x axis is the groups), so a histogram did not say which value it
shows. Fix: `histogram` re-enables the x title (`cellestial/single/core/distribution.py`);
`_distribution` and the theme are untouched.

Test: `test_histogram_names_the_plotted_value_on_the_x_axis`.

### 6. Unused categories make the dendrogram computation fail opaquely

Reproduction: `a.obs["g"] = a.obs[g].cat.add_categories(["Unused"])`, then any
plot with `dendrogram=True` raised pandas `KeyError: "['Unused'] not in index"`
from inside scanpy. Fix: `_dendrogram_info` checks for categories with no cells
before computing and raises `DendrogramMismatchError` naming them. A precomputed
dendrogram is unaffected.

Test: `test_dendrogram_with_unused_category_raises_clear_error`.

### 7. Cells sharing a barcode across groups are mixed in the per-cell heatmap

Barcodes repeat across samples when data is concatenated without making names
unique. Reproduction (`batch` groups whose second half reuses the first half's barcodes):

```python
names[200:] = names[:200]; local.obs_names = names
cl.retrieve(cl.heatmap(local, ["CD3D", "LYZ"], "batch", max_rows=None)).height
# 1600 rows, expected 400 cells x 2 keys = 800
cl.retrieve(cl.heatmap(local, ["CD3D", "LYZ"], "batch", max_rows=20))["position_y"].n_unique()
# 40 rows for max_rows=20, some bins averaging cells of both groups
```

Cause: `_bin_within_groups` matched each row to its bin by observation id only,
and `_assign_positions` attached `position_y` by observation id only, so a shared
id picked up both groups' bins/positions. Both bugs predate the `dev` rewrite.

Fix: both joins now match on the observation id and the group
(`cellestial/single/heatmap/utilities.py`). The `dev` oracle test
`_reference_bin_within_groups` (`tests/test_heatmap.py`) copied the old id-only
join and asserted the mixing for "same id in two groups"; its join was corrected
the same way, everything else in the oracle is unchanged.

Tests: `test_heatmap_keeps_cells_with_shared_barcodes_apart`,
`test_heatmap_bins_never_mix_groups_with_shared_barcodes`, plus the existing
`test_bin_within_groups_matches_reference_*`.

## Open issues (not fixed)

- **O1. `histogram` with several keys pools them into one histogram.**
  `cl.histogram(a, ["CD3E", "LYZ"])` draws one set of bars over both genes' values
  (30 bins, one group). Violin and boxplot put each key on its own x position, but
  the histogram never splits by `variable`. Not fixed because the obvious fix
  (mapping `fill` or `group` to the variable column) is an aesthetic promotion the
  project rules forbid without a decision. Options: warn and point to `histograms`,
  raise for more than one key, or map `group` (no colour) so bars stack per key.
- **O3. MuData: a bare `group_by` that exists both at the container and in the
  modality clusters the wrong column** (found by the bug-hunting pass on
  `pbmc_cite`). `cl.dotplot(m, keys, group_by="leiden", modality="rna", dendrogram=True)`
  plots the container's `leiden` (groups 0 to 8) but builds the dendrogram from
  `rna`'s own `leiden` (0 to 13): the tree is silently wrong in `dotplot`,
  `matrixplot` and `stacked_violin`. The per-cell `heatmap` and
  `annotated_heatmap` now raise `DendrogramMismatchError` (fix 2), whose
  "computed before the data was subset" hint is misleading for this cause. The
  root is `_Container.modality_column` mapping the bare name to the modality
  column; it belongs to the frames/MuData area.
- **O2. Group order for non-integer labels follows first appearance in the data,
  not category order** (matrixplot, dotplot, stacked_violin). This is the
  documented 0.62.1 behavior; the root cause (`build_frame` drops category order)
  is reported by the audit-core session and belongs to `cellestial/frames/`.

## Improvement suggestions (lower priority)

- **S1.** `_bin_within_groups` names bins by their index cast to `String`, and the
  rows are then sorted by that name, so within a group bins appear as 0, 1, 10, 11,
  ..., 2. Values are correct and cell order inside a group is arbitrary anyway, but
  zero-padding the name (or sorting the integer before the cast) would keep the bins
in barcode order (also affects `tracksplot`).
- **S2.** `matrixplot` has no explicit `modality` parameter. It works today only
  because `modality=` falls through `**geom_kwargs` into `heatmap`. Add it to the
  signature and docstring (guarded by `test_matrixplot_passes_modality_for_multimodal_dendrogram`).
- **S3.** `stacked_violin` draws no violin for a (key, group) whose values are all
  equal (typically all zeros), so that cell is empty rather than a flat line; scanpy
  draws a line. `fill_statistic` and `scale` values are not validated up front (an
  unknown `fill_statistic` silently drops the fill).
- **S4.** `_bin_observations` takes `mode().first()` for categorical annotations;
  with tied modes the chosen value may vary between runs.
- **S5.** `_annotation_scale` applies `scale_fill_manual` to a numeric track given a
  mapping of colors, which cannot work; a clear error would help.
- **S6.** `layout` and `_normalize_widths` raise builtin `ValueError`/`TypeError`
  rather than the classes in `cellestial/util/errors.py`, and reject numpy arrays for
  `widths`.
- **S7.** Per-cell `heatmap` group labels overlap for tiny groups (e.g. leiden
  5/20, 25/26), since each label sits at its group's center.
- **S8.** `tracksplot` keeps its own duplicate-keys check, now unreachable because
  `_resolve_key_groups` raises first with the same message; it could also use
  `_check_dendrogram_groups`.
- **S9.** `annotated_heatmap` docstring mentions `markers` under `modality` (it has
  no `markers`), and calls the dendrogram layer `geom_path` (it is a side line).
