## Confirmed bugs (fixed)

### B1. `xy` components outside the embedding build an unrenderable plot
- Reproduction: `cl.umap(pbmc3k, "leiden", xy=(0, 1))` returned a `PlotSpec`
  mapped to `X_UMAP0`; rendering failed with `ColumnNotFoundError`. Same for
  `xy=(1, 3)` on a 2D UMAP and `cl.pcas(..., xy=(1, 51))`.
- Fix: `dimensional` rejects `min(xy) < 1` before building, and raises when a
  component column is missing after building, naming the embedding and its
  component count (`InvalidArgumentError`, "components are 1-based").
- Tests: `test_dimensional_rejects_zero_based_components`,
  `test_dimensional_rejects_components_beyond_embedding`,
  `test_dimensionals_rejects_components_outside_embedding`.

### B2. Plural dimensional plots report an unknown key as a tooltip error
- Reproduction: `cl.umaps(pbmc3k, ["leiden", "leidn"])` raised
  `ValueError: Tooltip fields not in data: ['leidn']`.
- Cause: with a prebuilt frame, `dimensional` skipped key validation.
- Fix: validate the key against the data when it is not a frame column, so
  plurals raise `KeyNotFoundError: Key 'leidn' not found` (user frames with
  derived columns still work). Breaking only in the error class (CHANGELOG).
- Tests: `test_dimensional_plurals_unknown_key_raises_key_error`; two
  expectations in `tests/test_coverage_boost.py` that pinned the old
  `ValueError` were updated.

### B3. SpatialData spots matched to table rows by position, not instance key
- Reproduction: table rows listing instances `[3, 2, 1, 0]` over shapes
  `0..3`: `spot3` was drawn at x=0 instead of x=30 (every color on the wrong
  spot). A table covering 2 of 4 shapes failed with polars `ShapeError`.
- Fix: `_spatialdata_components` reorders point (and polygon-centroid)
  coordinates to the table's instance key, masks rows whose region is another
  shapes element, and leaves unmatched rows as NaN (dropped later). Without an
  instance key, a length mismatch raises `ConflictingLengthError`.
- Real data: on the Visium HD nucleus table, centroid mode now matches the
  polygon-join mode per instance within 0.33 px.
- Test: `test_spatialdata_points_align_on_instance_key` (reordered and subset).

### B4. `stream()` used positions as velocities for embeddings without `X_`
- Reproduction: `cl.dimensional(pancreas, "clusters", use_key="wnn_umap") +
  cl.stream()` (with `velocity_wnn_umap` present) read `WNN_UMAP1/2` as the
  velocity, since `"WNN_UMAP1".replace("X_", ...)` is a no-op, and drew
  streams of the position field without error.
- Fix: when the column has no `X_`, the velocity column is
  `velocity_prefix.upper() + column`; the missing-column error now fires.
- Tests: `test_stream_derives_velocity_for_unprefixed_embedding` (constant
  rightward velocity, all arrows point right),
  `test_stream_unprefixed_embedding_without_velocity_raises`.

### B5. `highest_expressed_genes(n<=0)`
- Reproduction: `n=-1` showed 23,426 genes (all but the last ranked), `n=0`
  built an empty plot.
- Fix: `InvalidArgumentError` for `n < 1`.
- Test: `test_highest_expressed_genes_rejects_non_positive_n`.

### B6. `elbow(n_pcs<=0)`
- Reproduction: `n_pcs=-1` showed 49 of 50 components; `n_pcs=0` an empty plot.
- Fix: `InvalidArgumentError` for `n_pcs < 1`.
- Test: `test_elbow_rejects_non_positive_n_pcs`.

### B7. `violins` / `boxplots` / `ridges` split a string `keys` into characters
- Reproduction: `cl.violins(pbmc3k, "CD14", group_by="leiden")` raised
  `ColumnNotFoundError: "C" not found`; `ridges` raised a tooltip error.
- Fix: a `TypeError` for a bare string only; arrays, `Index` objects and sets
  keep working (the bug hunter caught a first version that rejected them).
- Tests: `test_distribution_plurals_reject_string_keys`, `test_ridges_reject_string_keys`,
  `test_distribution_plurals_accept_array_like_keys`.

### B8. `xyplot` with a missing column reports a tooltip error
- Reproduction: `cl.xyplot(pbmc3k, "X_UMAP3", "X_UMAP1")` raised
  `ValueError: Tooltip fields not in data: ['X_UMAP3']`.
- Fix: `KeyNotFoundError` naming the column with close matches
  (`did you mean ['X_UMAP2', 'X_UMAP1', 'X_PCA3']?`). The check uses the
  plotted x/y after any `mapping` override.
- Tests: `test_xyplot_missing_embedding_component_raises_key_error`,
  `test_xyplot_mapping_override_skips_missing_column_check`.

### B9. `groups` / `drop` silently ignored without `group_by`
- Reproduction: `cl.violin(pbmc3k, "CD14", groups=["0"])` kept all 17,041 cells.
- Fix: `_distribution` warns that the filter is ignored and how to use it.
- Test: `test_violin_groups_without_group_by_warns`.

## Open issues (not fixed)

- O1. `build_frame` loses categorical order (`astype(str).cast(pl.Categorical)`
  orders by first encounter): Visium `clusters` legend reads 0, 2, 3, 4, 5, 7,
  6, 1, 8, 9. Lives in `frames/`, handed to the frames audit via the shared notes.
- O2. Polygon mode joins with `right_on=instance_key`, which drops the instance
  key column, so `add_keys=[instance_key]` or a tooltip on it fails with
  `ColumnNotFoundError`. Small, but a behavior change in `spatial.py` beyond B3.
- O3. Polygon mode ignores the region key: a table annotating several shapes
  elements with overlapping instance ids joins rows from other regions.
- O4. AnnData Visium with several libraries: `library_id` picks the image and
  scale factor but all libraries' spots are drawn on it. Matches scanpy's
  contract (subset first), so left as a documentation point.
- O5. A `mapping` that sets the aesthetic the function sets itself
  (`color` in `dimensional`/`spatial` with `key`, `fill` in `ridge`) raises a raw
  `TypeError: got multiple values for keyword argument`. Needs a design call
  (error or mapping wins).
- O6. `violin(data, "leiden", group_by="leiden")` raises polars `DuplicateError`
  rather than saying the key must be numeric.
- O7. Bare builtin errors remain where AGENTS.md asks for `errors.py` classes:
  `point_geom` and `axis_type` (`ValueError`), `xy` length (`KeyError`),
  `stream` velocity lookups (`KeyError`/`ValueError`), `cluster_outlines` groups
  (`ValueError`), spatial selection helpers (`KeyError`/`ValueError`). Changing
  the classes changes what callers catch, so left for a decision.
- O8. `cluster_outlines` with a pooled group of distant clusters (e.g.
  `["3", "5"]` on pbmc3k) uses one Scott bandwidth over the pooled points, so the
  outline is one wide blob bridging both clusters. Mathematically what a pooled
  KDE does; worth documenting or outlining each member separately.
- O9. `highest_expressed_genes` has an unused `observation_id_column` parameter.
- O10. Unknown keys get no close match: `_require_feature_key` (util) and
  `expression`'s `VariableNotFoundError`.
- O11. `ridge` maps `fill=group_by` itself, a hidden aesthetic promotion by the
  AGENTS.md rule. Pre-existing design.
- O12. `histograms` (outside this audit) has the same string-`keys` bug as B7.
- O13. `xyplot`/`xyplots` read `data.obsm`, `data.obs.columns` and
  `data.var_names` in the plot body instead of a backend helper.

## Improvement suggestions (lower priority)

- `dimensionals` applies `groups`/`drop` to every key; a mixed key list raises
  when one categorical key lacks the group. A per-call `group_key` would be clearer.
- `spatials` re-resolves the SpatialData components (transform, image load) once
  per key; resolving once and passing the result down would save time on large
  images.
- Label `pca` axes `PC1`/`PC2` (scanpy style) instead of `PCA1`/`PCA2`.
